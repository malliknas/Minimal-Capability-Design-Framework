Appendix E: MCD Heuristics and Diagnostic Table

Contents Overview

This appendix serves as a consolidated reference table of the MCD diagnostic heuristics introduced in Chapter 4, including methods for Capability Plateau detection, Redundancy Index calculation, Semantic Drift detection, and Prompt Collapse diagnostics.

Purpose Statement

To provide practitioners with a ready-to-apply toolkit for validating minimal agent designs and detecting over-engineering before deployment.

E.2 Detailed Heuristic Implementation Guidelines

E.2.1 Capability Plateau Detector

Implementation Protocol:
python

def detect_capability_plateau(prompt_tokens, semantic_score, resource_cost):
    if prompt_tokens > 90:
        efficiency_ratio = semantic_score / resource_cost
        if efficiency_ratio < 0.05:  # <5% improvement
            return "PLATEAU_DETECTED"
    return "WITHIN_BOUNDS"

Practical Application:
Monitor during design: Track token additions vs task completion improvements
Deployment threshold: Stop adding complexity beyond 90-token boundary
Resource calculation: Measure latency/memory cost per token added
Validation evidence: T1-T3 demonstrate plateau effects across multiple domains

E.2.2 Memory Fragility Score

Calculation Method:
python

def calculate_memory_fragility(stateless_accuracy, stateful_accuracy):
    dependence_ratio = (stateful_accuracy - stateless_accuracy) / stateful_accuracy
    if dependence_ratio > 0.40:  # 40% dependence threshold
        return "HIGH_FRAGILITY_RISK"
    return "STATELESS_READY"

Practical Application:
Test protocol: Run identical tasks with and without persistent state
Risk assessment: >40% dependence indicates deployment vulnerability
Validation method: T4 confirms 96% stateless reconstruction accuracy for MCD
Design implication: High fragility scores require architecture revision

E.2.3 Toolchain Redundancy Estimator

Usage Tracking Implementation:
python

def analyze_toolchain_redundancy(component_usage_log, execution_time):
    for component in component_usage_log:
        utilization_rate = component.usage_count / total_executions
        if utilization_rate < 0.10:  # <10% utilization
            latency_overhead = component.avg_latency
            return f"REMOVE_{component.name}_SAVES_{latency_overhead}ms"
    return "TOOLCHAIN_OPTIMIZED"

Practical Application:
Monitoring period: Track component usage over representative task cycles
Removal threshold: Components with <10% utilization should be removed
Performance impact: T7/T9 show 15-30ms latency savings from redundancy removal
Implementation: Systematic audit during development and pre-deployment

E.2.4 Semantic Drift Monitor

Real-time Detection:
python

def monitor_semantic_drift(q1_output, q4_output, similarity_threshold=0.90):
    semantic_similarity = calculate_cosine_similarity(q1_output, q4_output)
    if semantic_similarity < similarity_threshold:  # >10% drift
        return "ESCALATE_TO_Q4"
    return "MAINTAIN_Q1"

Practical Application:
Continuous monitoring: Compare outputs across quantization tiers
Automatic escalation: >10% drift triggers Q1→Q4→Q8 progression
Performance validation: T10 demonstrates effective tier selection
Edge deployment: Critical for maintaining quality under resource constraints

E.5 Practitioner Implementation Checklist

Pre-deployment Diagnostic Checklist:
Capability Plateau: Prompt complexity stays within 90-token efficiency boundary
Memory Independence: Agent achieves >90% accuracy without persistent state
Component Utilization: All tools/modules show >10% usage or are removed
Semantic Stability: <10% drift between quantization tiers under normal operation
Prompt Resilience: Maintains >94% success rate down to 60-token compression
Fallback Bounds: Recovery sequences terminate within 2 loops maximum
Context Regeneration: Stateless reconstruction maintains >90% accuracy
